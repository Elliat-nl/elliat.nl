How about dialects? Supporting XQuery 3.1 is cool, but in practice there are many dialects around.

  1. XQuery Update Facility adds some syntax sugar,
  2. XQuery Full Text adds syntax,
  3. Exist-DB has some update node syntax,
  4. BaseX has their own flavour of if/else conditions,
  5. Marklogic has their own flavour of XQuery
  6. More? Come talk to me!

By default the parser rejects dialects as they are syntax invalid

So how does it work?

I am presenting today a plugin to Prettier.

It uses Gunther Rademacher's REx parser generator

It supports dialects in an abstract way by making edits to the XQuery 4 grammar

It verifies correctness using the QT3/QT4 test set, plus a number of additional tests. It formats a test case, and reformats it to check it does not produce syntax errors, and makes sure the formatting is stable: does not cause a different format the second time around.

Prettier is a framework for formatters. It used to be JavaScript, but it is language-agnostic nowadays.

While this presentation is way too short to go into Prettier, a short rundown of how it works. It's DECLARATIVE!

  1. Parse code, stripping all whitespace
  2. Build a tree to determine where to place whitespace again
  3. Start printing: but whenever a group does not fit on a line, break it up where possible / allowed

See example

Now repeat this for all other places, choose where and how to break, and it's done!

🧪Dialects🧪

Experimental. Not fully implemented yet

So talking about dialects. As I stated before, there are numerous. And they all add their own keywords and syntax rules. While there is a grammar for XQuery 3.1 plus the ExistDB update syntax, there is none for the XQuery 4 yet.

And absolutely not for XQuery 4 plus ExistDB update syntax plus the BaseX if conditions

JavaScript solved this by with Babel: just parse everything

But we have even more challenges: the XQuery 4 spec is under flux, and I do not want to manually apply changes whenever the grammar changes

So I decided if I could come up with a way to express these dialects as amendments over the original grammar

Hoping they would not clash...

Amending grammars

  1. Take the XQ4 grammar
  2. Parse it
  3. Add new Rule to ExprSingle (for example)
  4. Add definition for that Rule
  5. Serialize to string
  6. Decide on formatting
  1. Amending a grammar is also declarative
  2. Take the grammar and parse it using a parser generated by the REX parser generator
  3. Add a new rule to what you want to override (in the case of ExistDB update node: ExprSingle
  4. Add a definition of that rule
  5. Serialize everything to string again
const existDBMutations = [
	{
		where: 'ExprSingle',
		name: 'ExistDB_UpdateExpr',
		additionalRule: `ExistDB_UpdateExpr ::= 'update' (
  ExistDB_UpdateInsertExpr |
  ExistDB_UpdateReplaceExpr |
  ExistDB_UpdateDeleteExpr |
  ExistDB_UpdateRenameExpr |
  ExistDB_UpdateValueExpr
)`,
	},
];
As illustrated by this example for the Exist DB node syntax. This (should be) extensible to the other dialects 
ExprSingle ::= ExistDB_UpdateExpr | ( FLWORExpr | QuantifiedExpr | SwitchExpr | TypeswitchExpr | IfExpr | TryCatchExpr | OrExpr )
ExistDB_UpdateExpr ::= 'update' ( ExistDB_UpdateInsertExpr | ExistDB_UpdateReplaceExpr | ExistDB_UpdateDeleteExpr | ExistDB_UpdateRenameExpr | ExistDB_UpdateValueExpr )
ExistDB_UpdateInsertExpr ::= 'insert' Expr (
    'into' | 'following' | 'preceding'
  ) ExprSingle
ExistDB_UpdateReplaceExpr ::= 'replace' Expr 'with' ExprSingle
ExistDB_UpdateValueExpr ::= 'value' Expr 'with' ExprSingle
ExistDB_UpdateDeleteExpr ::= 'delete' Expr
ExistDB_UpdateRenameExpr ::= 'rename' Expr 'as' ExprSingle
